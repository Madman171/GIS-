01-system-design.md

系统设计说明书

一、软件信息

项目 内容
软件名称 GIS交通路网教学知识图谱平台
软件版本 V1.0
软件类型 教学知识图谱可视化 Web 平台

前端技术 Vue 3、Vite、D3.js、Axios
数据库 Neo4j 5.x

二、建设目标

本软件面向 GIS 交通路网课程教学，将模块、知识点、前置关系、相关关系、 工具关系等内容组织为知识图谱，并通过网页提供目录浏览、图谱可视化、 知识点详情、媒体资源和智能问答能力。

三、总体架构

系统采用前后端分离架构：

浏览器
├── Vue 3 页面
├── D3.js 知识图谱
└── Axios API 客户端
        │
        ▼
FastAPI 后端
├── 目录与图谱接口
├── 知识点详情接口
├── 媒体访问
├── 搜索服务
└── DeepSeek 图谱问答服务
        │
        ▼
Neo4j 知识图谱数据库

前端负责页面布局和交互，后端负责数据查询、业务聚合和外部 AI 服务调用， Neo4j 负责保存教学知识图谱。

四、前端设计

页面框架

网页采用三栏式布局：

区域 功能
左侧 完整知识目录、模块折叠和知识点选择
中间 模块总览、知识点子图和详情面板
右侧 DeepSeek 智能问答和关联知识点引用

前端组件

组件 主要职责
App.vue 页面状态、接口调用、模块和知识点联动
DirectoryPanel.vue 知识目录、目录搜索和知识点选择
KnowledgeGraph.vue D3 力导向图、缩放、拖拽和节点点击
KnowledgeDetail.vue 知识点属性、关联知识和教学媒体
ChatPanel.vue 问答消息、配置状态和引用节点
api/client.js Axios 实例、基础地址和请求超时
constants/graph.js 节点颜色、类型和关系统一名称

页面状态

页面使用三个主要状态：

  1. 模块总览：只显示模块节点和模块关系。
  2. 模块知识点：显示当前模块和所属知识点。
  3. 知识点详情：在中间区域显示详情抽屉。

五、后端设计

应用入口

backend/main.py 负责：

  1. 创建 FastAPI 应用。
  2. 管理 Neo4j Driver 生命周期。
  3. 配置 CORS。
  4. 提供知识图谱、目录、搜索和问答接口。
  5. 挂载本地教学媒体目录。

配置模块

backend/config.py 从 backend/.env 读取：

  • Neo4j 地址、用户、密码和数据库名。
  • DeepSeek API Key、地址、模型和参数。
  • CORS 允许来源。

密钥和密码不写入前端代码，也不提交到源码仓库。

DeepSeek 服务

backend/deepseek_service.py 负责：

  1. 检查 API Key 是否配置。
  2. 使用 OpenAI 兼容 SDK 调用 DeepSeek。
  3. 设置系统提示词和回答约束。
  4. 处理超时、连接失败、状态异常和空回答。

模型不能直接生成并执行 Cypher。

六、数据设计

系统使用属性图模型：

(KnowledgePoint)-[:BELONGS_TO]->(Module)
(KnowledgePoint)-[:PREREQUISITE_OF]->(KnowledgePoint)
(KnowledgePoint)-[:RELATED_TO]->(KnowledgePoint)
(Module)-[:PREREQUISITE_MODULE]->(Module)
(KnowledgePoint)-[:HAS_MEDIA]->(Media)

节点业务主键：

标签 主键
Module module_id
KnowledgePoint kp_id
Tool tool_id
Media media_id

详细字段和关系统计见 02-database-design.md。

七、核心业务流程

模块总览

  1. 页面启动时读取目录和模块总览。
  2. 后端只读查询 Neo4j。
  3. 返回节点、关系和统计信息。
  4. D3 渲染模块力导向图。

知识点展开

  1. 用户点击模块。
  2. 前端请求模块子图接口。
  3. 后端查询模块、知识点和内部关系。
  4. 前端更新左侧目录和中间图谱。

知识点详情

  1. 用户点击知识点。
  2. 后端读取属性和关联节点。
  3. 后端查询 HAS_MEDIA。
  4. 前端显示详情抽屉和教学资源。

智能问答

  1. 用户输入问题。
  2. 后端取得当前模块和知识点。
  3. 根据问题关键词搜索相关知识点。
  4. 构建有限图谱上下文。
  5. DeepSeek 根据上下文生成回答。
  6. 返回答案和相关节点引用。
  7. 前端显示回答，点击引用可跳转。

八、安全设计

  1. 数据查询全部使用参数化 Cypher。
  2. 普通业务接口采用只读事务。
  3. 浏览器不能提交任意 Cypher。
  4. API Key 和数据库密码使用环境变量。
  5. 媒体导入检查路径穿越和文件扩展名。
  6. DeepSeek 输入限制为 500 个字符。
  7. 上游 AI 异常不会直接暴露 Key 或内部堆栈。

九、异常设计

场景 处理方式
Neo4j 不可用 健康检查返回 HTTP 503
知识点不存在 返回 HTTP 404
DeepSeek 未配置 返回 HTTP 503
DeepSeek 超时或服务异常 返回 HTTP 502
图谱为空 前端显示空状态
媒体为空 显示资源待添加状态

十、部署结构

开发阶段：

Vite 5173 -> FastAPI 8000 -> Neo4j 7687

生产阶段建议：

Nginx
├── 静态前端文件
└── /api 反向代理
        │
        ▼
Uvicorn/FastAPI
        │
        ▼
Neo4j

02-database-design.md

数据库设计说明

软件信息

项目 内容
软件名称 GIS交通路网教学知识图谱平台
软件版本 V1.0
数据库类型 Neo4j
数据库版本 5.26.30
数据快照日期 2026-09-20

数据模型概述

系统使用属性图模型存储教学知识内容。节点表示模块、知识点和工具， 关系表示知识点归属、前置依赖、相关内容、组成部分、应用关系以及工具实现关系。

数据库快照包含：

数据类型 数量
模块节点 9
知识点节点 344
工具节点 10
媒体节点 0
关系 1016
节点总数 363

节点设计

Module 模块节点

模块表示课程章节或教学主题。

属性 类型 说明
module_id 字符串 模块业务主键，例如 M1
name 字符串 模块名称
knowledge_count 整数 模块知识点数量
sort_order 整数 页面排序序号
order 整数 兼容排序字段，仅部分节点存在

唯一性约束：module_id。

KnowledgePoint 知识点节点

知识点表示模块中的具体教学内容。

属性 类型 说明
kp_id 字符串 知识点业务主键，例如 M1-001
name 字符串 知识点名称
description 字符串 知识点说明
difficulty 字符串 难度等级
importance 字符串 重要性等级
subcategory 字符串 分类名称
sort_order 整数 模块内排序序号

唯一性约束：kp_id。

Tool 工具节点

工具节点用于表示 GIS 平台、软件或技术工具。

属性 类型 说明
tool_id 字符串 工具业务主键
name 字符串 工具名称
category 字符串 工具类别
vendor 字符串 开发厂商或提供方

唯一性约束：tool_id。

Media 媒体节点

媒体节点用于保存视频和 PPT 课件的元数据，文件本体存放在后端媒体目录。

属性 类型 说明
media_id 字符串 媒体唯一标识
type 字符串 video 或 slides
title 字符串 资源标题
format 字符串 mp4、webm、pdf、ppt 或 pptx
url 字符串 浏览器访问地址
cover_url 字符串 视频封面地址，可选
order 整数 显示顺序

唯一性约束：media_id。

关系设计

关系类型 起点 终点 数量 含义
BELONGS_TO KnowledgePoint Module 344 知识点属于模块
PREREQUISITE_OF KnowledgePoint KnowledgePoint 86 前置知识点
RELATED_TO KnowledgePoint KnowledgePoint 41 相关知识
PART_OF KnowledgePoint KnowledgePoint 28 组成部分
APPLIED_IN KnowledgePoint KnowledgePoint 42 应用于
IMPLEMENTED_IN KnowledgePoint Tool 11 通过工具实现
PREREQUISITE_MODULE Module Module 5 模块前置关系
SUPPORTS Module Module 3 模块支撑关系
HAS_MEDIA KnowledgePoint Media 0 知识点关联媒体资源

所有关系均有明确方向。当前关系没有业务属性。

约束与索引

data/schema.cypher 定义以下结构：

  1. Module.module_id 唯一性约束。
  2. KnowledgePoint.kp_id 唯一性约束。
  3. Tool.tool_id 唯一性约束。
  4. Media.media_id 唯一性约束。
  5. 模块名称索引。
  6. 知识点名称索引。

数据导出文件

文件 用途
data/graph-snapshot.json 完整节点和关系快照
data/schema.cypher 约束与索引
data/modules.cypher 模块节点导入
data/knowledge-points.cypher 知识点节点导入
data/tools.cypher 工具节点导入
data/media.cypher 媒体节点导入
data/relationships.cypher 关系导入
scripts/export_graph.py 从 Neo4j 重新生成全部数据文件

数据恢复顺序

在空白 Neo4j 数据库中依次执行：

  1. data/schema.cypher
  2. data/modules.cypher
  3. data/knowledge-points.cypher
  4. data/tools.cypher
  5. data/media.cypher
  6. data/relationships.cypher

节点和关系导入均使用 MERGE，可以重复执行，不会因为重复导入而创建重复数据。

03-api-design.md

接口设计说明书

一、接口规范

所有业务接口使用 /api 前缀，默认返回 JSON。

通用成功格式：

{
  "code": 200,
  "message": "操作成功",
  "data": {}
}

问答接口成功时直接返回答案：

{
  "code": 200,
  "message": "问答成功",
  "answer": "回答内容",
  "references": [],
  "model": "deepseek-chat"
}

错误使用标准 HTTP 状态码：

状态码 含义
200 成功
404 资源不存在
429 提问过于频繁
422 请求参数错误
502 DeepSeek 上游异常
503 数据库或 AI 服务未就绪

二、健康检查

GET /api/health

检查 FastAPI 服务和 Neo4j 连接。

响应：

{
  "status": "ok",
  "message": "后端服务正常",
  "database": "connected"
}

三、模块总览

GET /api/graph/modules

返回模块节点和模块间关系。

响应数据：

{
  "nodes": [],
  "links": [],
  "summary": {
    "moduleCount": 9,
    "knowledgePointCount": null,
    "relationCount": 8
  }
}

节点格式：

{
  "id": "M1",
  "elementId": "...",
  "labels": ["Module"],
  "properties": {
    "module_id": "M1",
    "name": "基础理论与拓扑建模"
  }
}

关系格式：

{
  "id": "...",
  "type": "PREREQUISITE_MODULE",
  "source": "M1",
  "target": "M2",
  "properties": {}
}

四、目录接口

GET /api/directory

一次返回九个模块和各模块的知识点目录，数据量较小，不返回完整描述。

响应数据：

{
  "modules": [
    {
      "id": "M1",
      "name": "基础理论与拓扑建模",
      "properties": {},
      "knowledgePoints": [
        {
          "id": "M1-001",
          "name": "GIS交通路网的专业定义与核心研究范畴",
          "properties": {}
        }
      ]
    }
  ]
}

五、模块子图

GET /api/modules/{module_id}/graph

查询参数：

参数 类型 必填 说明
module_id 路径参数 是 模块业务主键
internal_relation_limit 查询参数 否 模块内关系上限，默认 800

返回模块、模块下全部知识点、BELONGS_TO 关系和知识点内部关系。

不存在的模块返回 HTTP 404。

GET /api/knowledge-points/{knowledge_point_id}

返回：

  • 知识点节点。
  • 所属模块。
  • 关联知识点、模块或工具。
  • 视频和课件资源。

示例：

{
  "node": {
    "id": "M1-001",

  "module": {
    "id": "M1",
    "labels": ["Module"],

      "name": "基础理论与拓扑建模"
    }
  },
  "relations": [],
  "materials": {
    "videos": [],
    "slides": []
  }
}

七、搜索接口

GET /api/search

查询参数：

参数 类型 默认值 说明
keyword 字符串 无 搜索关键词，长度 1 至 100
limit 整数 20 返回数量，范围 1 至 50

搜索模块和知识点的名称及描述。

八、DeepSeek 状态

GET /api/chat/status

响应：

{
  "configured": true,
  "model": "deepseek-chat",
  "message": "DeepSeek API 已配置"
}

该接口不返回 API Key。

九、智能问答

POST /api/chat

请求：

{
  "question": "什么是交通路网数据模型？",
  "module_id": "M1",
  "knowledge_point_id": "M1-001"
}

参数约束：

参数 必填 最大长度
question 是 500
module_id 否 50
knowledge_point_id 否 50

处理流程：

  1. 查询当前模块和知识点。
  2. 提取问题搜索词。
  3. 搜索相关知识点。
  4. 构建有限图谱上下文。
  5. 调用 DeepSeek。
  6. 返回答案和最多 12 个关联知识点。

十、媒体静态资源

GET /media/{path}

由 FastAPI 静态文件服务提供。

支持：

  • /media/videos/*
  • /media/slides/*
  • /media/covers/*

真实文件默认不进入源码仓库。

操作手册

一、系统启动

启动 Neo4j

确认 Neo4j 服务已启动：

bolt://localhost:7687
http://localhost:7474

cd E:\gis-knowledge-platform\backend

二、页面说明

页面分为三个区域：

  1. 左侧知识目录。
  2. 中间知识图谱。
  3. 右侧智能问答。

左侧知识目录

目录按模块组织知识点，并显示模块和知识点数量。

操作方法：

  1. 点击模块名称可以展开或折叠知识点。
  2. 点击模块名称会同步加载模块知识图谱。
  3. 点击知识点会打开知识点详情。
  4. 在搜索框中输入名称可以过滤模块和知识点。

中间知识图谱

初始状态显示模块总览。点击模块后显示该模块的知识点及内部关系。

图谱操作：

  1. 鼠标滚轮缩放。
  2. 拖动节点调整位置。
  3. 点击模块进入模块子图。
  4. 点击知识点打开详情。
  5. 使用左上角按钮放大、缩小和适应画布。
  6. 点击“返回总览”返回九个模块。

节点颜色：

颜色 类型
紫色 模块
蓝色 知识点
青绿色 工具，预留

知识点详情

详情面板显示：

  1. 知识点名称。
  2. 难度。
  3. 重要性。
  4. 分类。
  5. 所属模块。
  6. 知识点说明。
  7. 关联知识。
  8. 视频和课件。

点击关联知识可以继续跳转。

三、智能问答

右上状态显示：

  • 已连接：DeepSeek 已配置。
  • 待配置：尚未填写 API Key。

提问方法：

  1. 可先选择模块或知识点。
  2. 在右侧输入问题。
  3. 点击发送按钮或按 Enter。
  4. 等待回答。
  5. 点击回答下方的知识点引用可以跳转。

建议问题：

  • 什么是交通路网数据模型？
  • 轨迹数据有哪些关键技术？
  • 推荐一条学习路径。

四、维护知识图谱

新增知识点示例：

MATCH (module:Module {module_id: 'M1'})
MERGE (knowledge:KnowledgePoint {kp_id: 'M1-999'})
SET knowledge.name = '新的知识点',
    knowledge.description = '知识点说明',
    knowledge.difficulty = '中等',
    knowledge.importance = '重点',
    knowledge.sort_order = 999
MERGE (knowledge)-[:BELONGS_TO]->(module)

修改完成后刷新网页即可同步。只需改数据时不需要重启后端。

五、导入视频和 PPT

  1. 将视频放入 backend/media/videos。
  2. 将 PDF 或 PPT 放入 backend/media/slides。
  3. 将封面放入 backend/media/covers。
  4. 编辑 data/media-manifest.json。
  5. 执行检查：
cd E:\gis-knowledge-platform
backend\.venv\Scripts\python.exe scripts\import_media.py
  1. 检查通过后写入数据库：
backend\.venv\Scripts\python.exe scripts\import_media.py --apply

详细格式见 08-media-import.md。

六、常见问题

页面提示“连接异常”

检查后端和 Neo4j 是否启动，并访问：

http://localhost:8000/api/health

新修改的 Neo4j 数据没有显示

刷新浏览器页面。页面存在内存缓存，完整刷新后会重新获取。

DeepSeek 显示“待配置”

检查 backend/.env 中的 DEEPSEEK_API_KEY，并重启后端。

DeepSeek 返回服务异常

检查：

  1. API Key 是否正确。
  2. 账户是否有余额。
  3. 本机是否可以访问 DeepSeek。
  4. 网络是否稳定。

提示“提问过于频繁”

系统按 IP 限制提问频率，默认每分钟最多 5 次。稍等一分钟后再提问。

视频无法播放

建议使用 MP4 或 WebM。浏览器对编码格式支持不同，优先使用 H.264 编码 MP4。

PPT 无法在网页中预览

浏览器通常不能直接预览 PPTX。建议同时上传 PDF 预览版。

本软件面向 GIS 交通路网课程教学，将课程模块、知识点及其前置、相关、 组成部分等关系组织为知识图谱。系统提供完整知识目录、模块总览图、 知识点展开、知识点详情、视频和 PPT 资源扩展、全文目录搜索以及基于 DeepSeek API 的智能问答功能。用户可以从模块进入知识点，查看属性、 难度、重要性和关联知识，人工智能问答会结合当前图谱上下文回答， 并返回可供继续查看的相关知识点。

四、主要技术特点

  1. 使用 Neo4j 属性图模型存储教学知识结构。
  2. 使用 D3.js 实现模块和知识点力导向图。
  3. 使用 Vue 3 实现三栏式交互界面。
  4. 使用 FastAPI 提供参数化只读查询接口。
  5. 使用 DeepSeek API 实现知识图谱增强问答。
  6. 使用独立媒体目录和 HAS_MEDIA 关系扩展教学视频及课件。
  7. 提供数据库快照、自动化测试和软著源码整理脚本。

五、运行环境

操作系统：Windows 10/11 或主流 Linux
浏览器：Microsoft Edge、Chrome 等现代浏览器
后端：Python 3.12+
前端：Node.js 24+
数据库：Neo4j 5.x
网络：智能问答功能需要访问 DeepSeek API
